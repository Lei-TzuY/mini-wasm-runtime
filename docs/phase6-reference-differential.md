# Phase 6 reference differential tranche

The repository has an isolated reference-engine test workspace under `differential/`. It compiles supported WebAssembly modules from WAT, executes the exact same bytes in the mini runtime and Wasmtime, normalizes observable outcomes, and compares both engines against explicit expectations.

The fixed corpus covers integer wrapping and rotation, `nop`/`drop`/untyped `select`, indexed/default `br_table`, f32/f64 bit-level edge behavior, typed memory round trips, `memory.grow`, and representative execution traps.

The differential harness compares exact normalized trap classes shared by both engines. The original classes cover memory out-of-bounds, signed integer division overflow, integer division by zero, and invalid float-to-integer conversion. The table tranche adds table out-of-bounds, indirect call to an uninitialized element, and indirect-call signature mismatch. Unmapped mini-runtime errors or Wasmtime traps fail closed rather than collapsing into generic trap equivalence.

A deterministic generated numeric tranche emits 96 i32 modules from a committed seed across wrapping add/sub/mul and bitwise and/or/xor. Every case includes the seed and case index in diagnostics, and each compiled module is executed unchanged by both engines.

A deterministic stateful tranche emits 64 modules combining a mutable i32 global with persistent linear memory. Each module is invoked four times on one mini-runtime instance and one Wasmtime instance. The reference recurrence independently predicts the full four-call sequence, which checks state persistence, wrapping updates, memory load/store behavior, and cross-invocation observability together.

A table-dispatch state tranche emits 64 modules with two initialized funcref targets and a mutable selector that alternates the `call_indirect` target across six invocations. Both engines must produce the exact alternating target-result sequence. A separate structured multi-value tranche emits 96 `if (result i32 i64)` modules and checks exact value ordering and branch selection through the mini runtime's values API and Wasmtime's typed tuple ABI.

The imported/shared-state tranche emits 48 deterministic modules importing a mutable i32 global and a bounded linear memory. Host code seeds both objects before instantiation, applies a second external override in the middle of each five-call sequence, and checks both guest-returned `(i32, i32)` results and host-visible backing state after every invocation. A dedicated two-instance fixture links the same imported global and memory into two live instances in each engine and alternates calls between them, verifying that guest writes in one instance are observed by the other and by the host.

The imported-function tranche emits 48 deterministic modules importing an `i64 -> i64` host callback. Each callback owns host-side wrapping state, every module is invoked five times, and an independent recurrence predicts both the callback state and the guest-visible post-call XOR result. A second fixture binds two guest instances to one host state per engine and alternates calls between them, while a mixed numeric ABI fixture checks `i32`, `i64`, `f32`, and `f64` parameter ordering and bit-preserving host observation against Wasmtime.

The imported-table tranche imports a bounded funcref table, lets active element segments initialize two defined targets, and then drives 64 deterministic indirect calls through both engines. It also relocates a function reference through the host table API, clears a slot to compare the null-indirect-call trap, and checks that accepted/rejected import-limit combinations agree with Wasmtime. Cross-instance aliasing is deliberately not claimed: mini-runtime table references are instance-bound and one `TableHandle` currently rejects attachment to two live instances.

The host-memory tranche imports a callback that reads an i32 from guest memory, applies a wrapping update, writes it back, and returns the new value. Ninety-six deterministic calls spread across 16 word-aligned slots compare both the callback result and the guest's immediate post-call load with an independent state model in the mini runtime and Wasmtime. Mini-specific security checks separately prove that read access is denied under `HostCapabilities::NONE`, write access is denied under `MEMORY_READ`, and an out-of-bounds host read leaves memory unchanged.

The host-failure tranche executes 96 deterministic calls with successful and intentionally rejected imported callback invocations interleaved. Both callbacks increment host-owned call state before deciding whether to reject. Successful calls must match an independent recurrence, while rejected calls normalize to one semantic callback-failure class, leave the guest success counter unchanged, and permit subsequent invocations to recover. Wasmtime classification downcasts the original custom host error type through its error context chain; it does not depend on error-message wording. The mini runtime is matched at its typed `HostCallFailed` boundary and additionally checks the sentinel `HostError::Message` payload so unrelated host errors cannot collapse into the same class.

The automatic capture/shrink tranche adds 64 deterministic i32 modules across wrapping arithmetic, bitwise operators, shifts, and rotates. When mini and Wasmtime disagree, the harness first requires Wasmtime to match an independent Rust-side semantic model; otherwise it refuses to produce a mini-runtime regression. Eligible mismatches are re-executed while operand candidates move monotonically toward lower-magnitude canonical values, retaining only reductions that preserve the same reference-backed disagreement. The minimized WAT, a replay-manifest-compatible row, and seed/case/original/minimized outcome metadata are written to `differential/target/differential-captures/`. On a failed differential CI run, `actions/upload-artifact` preserves any generated captures for seven days. The harness deliberately stops short of mutating the committed regression corpus: promotion remains a reviewed step.

The memory mismatch-capture tranche broadens the same mechanism to execution state and traps. Ninety-six deterministic one-page modules write and reload generated i32 values at generated base addresses with memarg offsets chosen from `0, 1, 2, 3, 4, 7, 16, 64, 255`. An independent model computes the unsigned effective address plus the four-byte access width and predicts either the exact reloaded value or `memory_out_of_bounds`. Reference-backed mismatches are reduced across base address, offset, and stored value using a strictly decreasing lexicographic complexity rank, with boundary-aware candidates around the final four valid bytes of the page. Captures are emitted directly in the existing replay-manifest vocabulary as either `i32` or `trap memory_out_of_bounds` rows.

The multi-value mismatch-capture tranche adds 96 structured `if (result i32 i64)` modules. Every third case forces a zero condition, while the remaining cases use non-zero generated conditions, so both branch paths are guaranteed to execute. An independent model selects the expected `(i32, i64)` tuple before either engine runs. Eligible disagreements are reduced across the condition, active branch values, and inactive branch values with a strictly decreasing rank, then emitted in the replay corpus's existing `pair_i32_i64` manifest form.

The table mismatch-capture tranche adds 96 deterministic `call_indirect` modules over a fixed two-slot funcref table. The corpus deliberately includes successful slot-0 and initialized slot-1 calls, uninitialized slot-1 null calls, and selectors beyond the table length. An independent model predicts the exact i32 target result or the normalized `indirect_call_to_null` / `table_out_of_bounds` trap. Eligible mismatches are reduced across selector, whether the second slot is initialized, and both target constants under a strictly decreasing rank, then emitted using the replay corpus's existing `i32` and trap forms.

The imported-function mismatch-capture tranche moves the reducer across an actual host boundary. Forty-eight deterministic modules import a stateful `i64 -> i64` callback, invoke it one to five times, and XOR each callback result with a generated guest salt. An independent recurrence predicts the complete result trace and final host-owned wrapping state before either engine runs. A mismatch is eligible only when Wasmtime matches that full recurrence. The reducer then shortens the call sequence and simplifies the initial state, guest salt, and each input under a strictly decreasing lexicographic rank. Captures include minimized WAT, provenance metadata, and a companion `.import.tsv` driver containing the host behavior identifier, initial state, inputs, expected guest result sequence, and expected final host state.

The import-aware replay tranche adds a reviewed destination for those driver-complete artifacts under `tests/fixtures/import_regressions/`. Its eight-field manifest uses the same row layout as `.import.tsv` captures. Before either engine runs, the harness validates IDs, paths, host behavior, trace lengths, numeric fields, and independently recomputes the entire `stateful_i64_add` guest-result trace and final host state. Each WAT is compiled once, then the mini runtime and Wasmtime are both linked to equivalent stateful hosts and must match the declared trace exactly. Seeded ordinary and wrapping fixtures prove the promotion format without claiming production bugs.

The initial no-import differential regression replay layer keeps a separate manifest and 10 manually minimized seeded WAT reproducers. It covers `br_table` default-result preservation, f64 signed-zero `min`, structured `(i32, i64)` ordering, memory OOB, signed integer divide-by-zero and overflow, invalid float-to-integer conversion, null indirect calls, table OOB, and indirect-call signature mismatch. The runner validates manifest integrity and path safety, compiles each WAT once, then requires the exact same Wasm bytes to match the declared normalized result in both engines. These seeded reproducers establish the replay format without implying that each fixture came from a previously observed bug.

The differential workflow runs every integration target in the nested workspace, so future differential tranches do not require editing the CI command to become active.

Wasmtime and WAT remain confined to the nested workspace and dedicated Ubuntu CI job; no product dependency, workspace member, or Rust 1.81 MSRV change is introduced. Imported global/memory/table capture-and-replay domains, additional stable typed host-failure classes, broader stateful corpora, reviewed promotion assistance, and additional trap taxonomy remain follow-up work.
